Viewport-Aware Shader Rendering

This example demonstrates how to use the same shader source on multiple canvas elements, with intelligent viewport detection to pause rendering when not visible.

Scroll down to see three shader canvases. Each one only renders when it's visible in the viewport, saving GPU resources and improving battery life on mobile devices.

Canvas 1 – Phase 0°

How It Works

IntersectionObserver API

We use the browser's IntersectionObserver to detect when each canvas enters or leaves the viewport. This is much more efficient than listening to scroll events.

  • Zero scroll event listeners needed
  • Native browser optimization
  • Configurable threshold for trigger point
  • Works with CSS transforms and scroll containers

Performance Benefits

  • GPU only renders visible canvases
  • Reduced power consumption
  • Better battery life on mobile
  • Smoother scrolling performance
Canvas 2 – Phase 120°

Implementation Pattern

// Create observer for viewport detection
const observer = new IntersectionObserver((entries) => {
  entries.forEach(entry => {
    isVisible = entry.isIntersecting;
  });
}, { threshold: 0.01 });

// In onBeforeFrame callback
onBeforeFrame: function(ctx) {
  if (!isVisible) return; // Skip rendering
  // ... rest of your code
}

Shared Shader Source

All three canvases share the same shader source code defined once in the HTML. Each instance gets a unique phase offset via the iPhase uniform, creating visual variety without code duplication.

Canvas 3 – Phase 240°

Key Takeaways

  • Use config.canvas to target specific canvas elements
  • IntersectionObserver is the most efficient visibility detection
  • Return early in onBeforeFrame to skip rendering
  • Consider document.hidden for tab visibility too
  • Each shader instance maintains its own WebGL context
